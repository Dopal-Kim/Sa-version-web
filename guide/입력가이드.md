# SA 6번 탭(확률 공정 · 대응안) 입력 가이드

작성 2026-10-21 · 브랜치 `sa-ai-redesign` · 입력 파일은 [inputs/](inputs/)

표기: **[근거]** 공식 문서·법령·논문 원문에서 확인한 값 / **[2차]** 보도·요약 사이트에서 확인(원문 대조 권장) / **[가정]** 근거 없이 정한 값 → 본인 현장 값으로 바꿔야 함

---

## 1. 실행

```bash
cd sa_repo
python -m http.server 8766 --bind 127.0.0.1
```
브라우저에서 `http://127.0.0.1:8766` → 상단 **확률 공정 · 대응안** 탭.

1. 카드 A 아래 **입력값 불러오기** → `inputs/ex*.json` 선택 → **계산**
2. 값을 바꿔 본 뒤 **입력값 저장**하면 같은 형식(`sa-input/1`)의 파일로 내려받아짐
3. 결과는 난수 시드가 고정이라, 입력이 같으면 아래 기대값과 정확히 같게 나와야 함 (기상 연도별 변동을 켠 경우만 예외: 매번 최신 실측을 받음)

## 2. 예제 입력 파일과 기대 결과

| 파일 | 무엇을 확인하나 |
|---|---|
| `ex1_LH별표8_795일.json` | LH 지침 원문 예시를 앱이 그대로 계산하는지 |
| `ex2_서울20층_유로폼_공공.json` | 앱 기본값. 대응안 비교의 대표 예시 |
| `ex3_메이플자이_정비사업_역검증.json` | 실제 준공 사업의 공기가 예측 분포의 어디에 떨어지는지 |
| `ex4_민간PF_책임준공.json` | 책임준공 기한·손실 평가 |
| `ex5_Revit내보내기_예시.json` | Revit 연동(카드 G) — **입력값 불러오기가 아니라 카드 G의 파일 선택에 넣음** |

### ex1 — LH 별표8 예시 (서울, 2016-09-14 착공, 지하1(4.5m 초과)·지상20층, 시스템 거푸집, 선굴착 파일 25m·2,000본)
- **LH 기준 795일, 2018-11-17 준공, 동절기 층 15~20층** ← LH 지침 별표8 계산 예시와 같아야 정상
- 구간별 계산(카드 B 펼치기): 준비 30 / 토공 37(작업 24+비작업 13) / 기초 81(51+30) / 지하골조 116(78+38) / 지상골조 253(157+96) / 습식마감 184(125+59) / 건식마감 44(30+14) / 정리 30
- P50 874일, 보정 P80 1,096일, 계약 공기(=LH 795일) 내 준공 17%, ±15% 대칭이면 P80 922일
- 대응안 1위: 마감 층별 선행 착수 + 마감 작업조 1개 추가 (기한 내 73%, 보정 P80 848일)

### ex2 — 서울 20층 유로폼 공공 (2026-03-02 착공, 계약 1,500억 [가정])
- LH 기준 974일(2028-10-30), 동절기 층 1~4·20층
- P50 1,029 / 보정 P80 1,238 / 기한 내 24% / 기대 지연 124일 / ±15% 대칭 P80 1,051
- 대응안 1위: 시스템 거푸집 + 마감 층별 선행 착수 → 기한 내 90%, 보정 P80 910일, 대응비 6억, 기대 총비용 145.3억(대응 없음 255.9억)
- 확인 포인트: '골조 연장근무'만 단독이면 12위(대응비 36.9억, 안전 노출 ×1.5) — 비용·안전 부작용이 반영되는지

### ex3 — 메이플자이(신반포4지구) 정비사업 (2021-10-19 착공, 35층·지하4층, 계약 34개월 = 1,034일)
- LH 기준 1,122일 / P50 1,258 / 보정 P80 1,479 / 계약 내 준공 8%
- **실제 공기 44.3개월 ≈ 1,347일**(조선비즈 2025.4.18) → P50과 보정 P80 사이에 들어감(분포가 실제를 덮음)
- 기사에 없는 입력(시스템 거푸집·주차 150대 이상·어스앵커·파일 25m 2,000본·4.5m 초과 지하 1개층)은 [가정] — `research/scripts/kr_validate.mjs`와 같은 값
- 다른 6건도 같은 방식으로 직접 넣어볼 수 있음: `research/data/kr_cases.csv`(use=validate). 계약 공기 = 계획 개월 × 30.4

### ex4 — 민간 PF 책임준공 (ex2 건물, 민간 모드, 책준 기한 2029-01-31 [가정], 대출원리금 1,200억 [가정], 판례형)
- P50 971 / 보정 P80 1,079 / 책준 기한 내 80% / **책준 기대 손실 238.8억**
- 1위: 시스템 거푸집 + 마감 선행 착수 → 책준 기한 내 96%, 기대 손실 48.6억
- 판례형 → 모범규준형(경과일/90)으로 바꾸면 손실이 줄어드는지 비교해 볼 것
- 주의: 민간 모드는 국내 정비사업 7건 역검증에서 P80 안 4/7로 낙관적. 분쟁 가능성이 있으면 정비사업 모드 사용

### ex5 — Revit 내보내기 예시 (예시 공동주택 101동)
카드 G에서 파일 선택 → 상태 줄에 아래 문구가 나오고 입력칸이 바뀌면 정상:
> 지상 15층·지하 1층(4.5m 초과 1)·요소 7개·연면적 12,400㎡·거푸집 근사 10,400㎡ → 입력칸에 반영

(지상 15, 지하 1, 파일 선굴착 22m·420본, 연면적 12,400). **계산** 후 'Revit 결과 JSON'·'TimeLiner CSV' 버튼이 켜짐.

### 3-2. 작업기간 분포 (화면 입력 없음, 앱에 내장)

## 4. Revit 연동 (직접 해볼 때)

1. pyRevit 설치(https://github.com/pyrevitlabs/pyRevit/releases) → pyRevit 설정 → 사용자 확장 폴더에 `sa_repo/revit` 추가(또는 `SA.extension` 폴더를 `%APPDATA%\pyRevit\Extensions`에 복사) → Reload → 리본에 SA 탭
2. Revit 모델 조건: 층으로 셀 레벨만 **Building Story** 켜기(꺼진 레벨은 무시, 고도 0 아래 = 지하). 레벨 이름에 roof·지붕·옥탑·PH·parapet·파라펫이 있으면 지붕층으로 보고 층수에서 뺌. 파일은 구조 기초의 패밀리·유형 이름에 pile·파일·PHC·말뚝·SIP·강관이 있으면 본수로 셈(깊이는 내보낼 때 물어봄)
3. SA 탭 → **SA 내보내기** → `sa-revit/1` JSON 저장 → 앱 카드 G에 넣기 → 계산
4. 앱에서 **Revit 결과 JSON** 받기 → Revit **SA 가져오기** → 요소에 `SA_P50_Finish`·`SA_P80_Finish`·`SA_Risk` 매개변수 기록, 현재 뷰에서 위험도 색칠
5. Navisworks: TimeLiner → 데이터 소스 → CSV 가져오기. CSV 열: Task Name, Synchronization ID(=활동 ID), Planned Start, Planned End, Task Type, User 1 (P80 Finish), User 2 (Risk) → 각각 작업 이름·동기화 ID·계획 시작·계획 끝·작업 유형·사용자 1·사용자 2에 매핑. 요소 연결은 규칙 기반 첨부에서 SA_Activity 매개변수 = 동기화 ID
6. 아직 실제 Revit에서 돌려보지 않았음(IronPython 문법 맞춤, 라이브러리 자가검사만 통과). 오류가 나면 pyRevit 출력 창 내용을 보내 주세요
